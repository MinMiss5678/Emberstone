# Emberstone：Rust 爐石引擎與 AI 研究規劃

狀態：已核可（2026-10-31 改版）。骨架已建立。前身巫妖王模擬器的紀錄見 `docs/背景研究.md`（已移出範圍，僅供參考）。

## 1. 目的

1. **練習 AI 工程技能**：從規則 AI、搜尋、學習式評估、強化學習，到 LLM 代理，在同一個環境裡逐步實作與比較。
2. **研究標準模式的玩家對戰**：雙方都是自組牌組、資訊不完全的對戰，不再做單人副本。

產出三樣東西：
- **盡量強的對戰 AI**（規則 → 搜尋 → LLM → 學習式，逐代比較）。
- **牌組之間的勝率矩陣**：指定一組牌組，用 AI 代打互相對戰，輸出勝率與信賴區間。
- **自動構築牌組**：在指定卡池（可限定使用者收藏 `collection.json`）中搜尋對指定環境勝率最高的 30 張；以演化演算法為主，LLM 負責提出候選與修改理由，模擬器負責評分。

不做：巫妖王與其他單人副本、英雄戰場、競技場選牌。**不在天梯實際對戰中使用**（違反使用條款）：只做離線模擬、牌組評估與復盤分析。

## 2. 卡池與驗證策略

範圍是**現行標準模式**（核心系列＋最近兩年的資料片，約 1,300 張），分批完成，**先做能找到參考答案的卡**。

| 批次 | 內容 | 張數（2026-10 統計） | 驗證方式 |
|---|---|---|---|
| A | 核心系列中 RosettaStone 已實作、且數值與敘述和現行版相同的卡 | 96（死亡騎士以外 10 職業＋中立；清單見 `data/batches.tsv`） | **差分測試**：和 RosettaStone 同步跑隨機對局，逐步比對狀態 |
| B | 核心系列中 RosettaStone 有實作（同卡號或原版），但數值或敘述和現行版不同的卡（部分可能只是措辭改版） | 57 | 差分測試，參考引擎端套用現行數值；行為不同處逐張列 case |
| C | 核心系列其餘卡（含死亡騎士 34 張：符文、屍體） | 136 | **實戰紀錄重播**＋規則 case 表 |
| D | 標準資料片（翡翠夢境、安戈洛迷城、時光特攻隊、浩劫與重生、紫羅蘭堡大逃亡、黑暗帝國霸業） | 約 1,010 | 實戰紀錄重播＋規則 case 表；依研究需要挑系列 |

- **差分測試**：兩個引擎用同一組牌、同樣的行動序列、**同樣的隨機結果**跑對局，每一步比對雙方狀態；不一致即為錯誤。RosettaStone 不是絕對正確，有爭議的案例逐一列給使用者裁定。需要先在 RosettaStone（我們的副本）加入「亂數由外部指定」與「狀態輸出」介面。
- **實戰紀錄重播**：把 Power.log 的實際對局逐步餵給引擎，比對每一步後的狀態和遊戲紀錄。只能涵蓋實際出現過的卡與互動。
- 卡片數值與敘述一律由 HearthstoneJSON 現行版產生；每次版本更新重新產生並重跑全部驗證。

## 3. 架構

Cargo workspace，相依只有一個方向：data → core → cards → ai → sim／py。

| crate | 內容 |
|---|---|
| `emberstone-data` | 卡表產生工具：由 HearthstoneJSON `tw_all.json`（複製到 `data/`）產生 Rust 表格並納入版本控制，含台版卡名 |
| `emberstone-core` | 對局狀態、規則、事件佇列、觸發、光環、附魔、亂數、合法行動列舉、複製；**行動編號與狀態特徵輸出**（給學習用）、**狀態與行動的文字描述**（給 LLM 用） |
| `emberstone-cards` | 卡片效果 |
| `emberstone-ai` | 隨機、規則 AI、搜尋 AI（決定化＋MCTS）、學習式評估的推論端 |
| `emberstone-sim` | 命令列：對戰模擬、牌組勝率矩陣、速度量測、報告（繁體中文） |
| `emberstone-py` | **必要**：PyO3 模組，提供 Gym 風格環境（reset／step／合法行動遮罩／特徵）、批次平行模擬；訓練與 LLM 代理在 Python 端 |
| `tools/` | 差分測試工具：RosettaStone 橋接程式（C++，Windows 上以 MSVC 編譯，加上亂數指定與狀態輸出）與比對程式；詳細拆法在第 0 階段 case 表定案 |

外部套件盡量少：core、cards、ai 不用外部套件；data 產生工具用 serde／serde_json；sim 用 clap、mimalloc（選用）；py 用 pyo3。

### 核心設計
- **狀態**：實體存在 `Vec<Entity>`，以編號互相參照；整份狀態 `#[derive(Clone)]`，複製要維持微秒等級（搜尋 AI 的命脈）。
- **事件與時序**：照爐石的階段規則處理（出牌 → 戰吼 → 召喚後觸發 → 死亡階段 → 死亡之聲依上場順序）。
- **亂數**：每局一個可複製的亂數產生器，同種子可重現；亂數來源可替換成「外部指定」，供差分測試與重播使用。
- **隱藏資訊**：每位玩家只能取得自己視角的觀測（對手手牌、牌庫順序不可見）；搜尋 AI 用決定化重抽隱藏資訊。
- **行動空間**：合法行動有穩定的編號與遮罩，讓強化學習可以直接使用。
- **卡片效果**：以效果列舉組合為主，特殊卡用函式；未實作的隨機生成卡退化成「只有數值和關鍵字」，並統計發生次數。

## 4. 階段（每段都照 test-first：case 表核可 → 測試 → 紅燈 → 實作 → 綠燈）

| 階段 | 內容 |
|---|---|
| 0 工具 | 卡表產生（0a，完成）；差分測試工具：批次分類、RosettaStone 橋接程式（亂數記錄／重播、狀態輸出、合法行動）、比對與驗收命令（0b，完成）。速度量測移到第 1 階段 |
| 1 基本規則 | （完成）回合、法力、超載、出牌、攻擊、嘲諷、聖盾術、致命劇毒、生命竊取、風怒、衝鋒／衝刺、潛行、凍結、武器、護甲、疲勞、手牌／戰場上限、死亡處理；以白板與純關鍵字手下做差分測試（case 表：`docs/第1階段-case表.md`） |
| 2 事件框架 | 英雄技能、戰吼、死亡之聲、觸發、光環、附魔、變形、衍生物、二選一、發現 |
| 3 卡片批次 A、B | 約 153 張核心卡，全部通過差分測試 |
| 4 AI 基礎與評估 | 隨機、規則 AI；評估框架（勝率與信賴區間、Elo、固定種子）；**勝率矩陣**命令；`emberstone-py` 環境 |
| 5 搜尋 AI | 決定化＋MCTS，善用複製速度 |
| 6 LLM 代理 | 文字介面＋工具呼叫出牌；和搜尋 AI 比強度、比成本 |
| 7 學習式 AI | 以自我對戰資料訓練評估函式；強化學習（PPO 自我對戰等） |
| 7.5 自動構築牌組 | 演化演算法＋勝率矩陣評分；LLM 提案；可限定使用者收藏。可在第 5 階段之後提前做（用當時最強的 AI 代打） |
| 8 卡片批次 C、D | 實戰紀錄重播驗證；依研究需要逐系列加入 |

第 8 階段可以和 4–7 交錯進行。每個階段結束都能單獨使用。

## 5. 驗收方式
1. 卡片：批次 A、B 在差分測試中跑 N 局（N 於第 0 階段 case 表定案）沒有任何不一致；批次 C、D 的實戰紀錄重播全部一致。
2. 速度：一局 ≤ 0.5 ms、複製 ≤ 5 μs（以批次 A 的卡組成的牌組、Windows 量測）。
3. AI：每個 AI 都要對前一代有統計顯著的勝率提升，或明確記錄沒有提升的原因。

## 6. 風險與對策
| 風險 | 對策 |
|---|---|
| 規則時序寫錯，勝率失真 | 第 2 階段專做事件框架；差分測試與實戰紀錄重播雙重驗證 |
| 參考引擎本身有錯 | 不一致時不預設任一方正確，逐案列給使用者裁定 |
| 只用批次 A、B 的卡組不出像樣的牌組 | 研究初期接受「實驗用牌組」；第 8 階段補卡後再研究實際環境牌組 |
| 新資料片與平衡調整 | 數值自動產生；效果按研究需要補；驗證可整批重跑 |
| LLM 代理成本與速度 | 用較少局數評估；記錄每局費用與時間 |
| 隨機生成卡無法全部實作 | 退化成白板並統計次數 |
