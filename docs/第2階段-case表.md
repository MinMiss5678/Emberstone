# 第 2 階段：事件框架 case 表

使用者已核可（2026-11-01）。期望值照爐石現行規則；和 RosettaStone 不同時不預設參考引擎正確。

## 範圍與做法

- 英雄技能、指定目標、法術傷害、戰吼、死亡之聲、觸發、被動加成、附魔、變形、衍生物、二選一、發現、沉默、秘密。
- 每個機制挑 1～3 張批次 A（或 RosettaStone 已實作、數值一致）的卡實作成範例；其餘卡片留到第 3 階段。
- core 只提供框架與效果種類；卡片效果寫在 cards，開局時交給 core。幸運幣也搬到 cards。
- 隨機效果對齊 RosettaStone 的抽亂數方式（類型、範圍、候選順序），每張隨機卡的抽法寫在程式註解，差分測試才能重播。
- 名稱：暴風城勇士這類「在場上就讓其他手下加數值」的效果叫「被動加成」；「光環」保留給聖騎士的光環法術（第 3 階段以後）。

## 實作結果（2026-11-09）

- 規則測試：`crates/emberstone-cards/tests/` 共 80 個，`crates/emberstone-core/tests/` 照常全部通過；橋接程式測試 `tools/difftest/tests/bridge.rs` 共 44 個全部通過。
- G1：`difftest run --engine emberstone --pool keywords --powers --games 1000`，種子 1–4 都是一致 1000/1000，RosettaStone 錯誤 0 局。
- G2：`difftest run --engine emberstone --pool stage2 --powers --games 1000`，種子 1–10 都是一致 1000/1000，RosettaStone 錯誤 0 局。
- G3（Windows、release、`emberstone bench --games 10000`，跑 3 次）：每局平均 0.22–0.28 ms、第 10 回合複製一次 0.59–0.71 μs。第 1 階段是 0.117 ms／0.60 μs：每局約慢 2 倍（事件框架、被動加成重算、秘密與死亡階段），複製幾乎不變；仍在第 3 階段門檻（0.5 ms、5 μs）內。

### 對照時發現的 RosettaStone 問題

RosettaStone 和 case 表不同的地方都以 patch 修正（`tools/rosetta-bridge/patches/` 的 `0005`–`0025`，各自的說明見 `tools/rosetta-bridge/README.md`），每個 patch 都先有橋接程式測試的紅燈。差分測試中途浮現、由使用者裁定或實測定案的規則：C1、C6、C7、D6、E2a、F1b、F2a、F4b、I3a–I3d、I4a，以及第 1 階段的 B3a、D9a。
