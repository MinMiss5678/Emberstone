# 第 1 階段：基本規則 case 表

使用者已核可（2026-11-01）。期望值照爐石現行規則；和 RosettaStone 不同時不預設參考引擎正確。

## 範圍

- 只有卡片數值與關鍵字（嘲諷、聖盾術、衝鋒、衝刺、風怒、致命劇毒、生命竊取、潛行、凍結、超載）和幸運幣。
- 英雄技能放第 2 階段；差分測試排除「使用英雄技能」。
- 戰吼、死亡之聲、觸發、光環等卡片效果放第 2 階段。

## A. 開局與可重現性

| # | 情境 | 期望 |
|---|---|---|
| A1 | 開局 | 照抽牌順序：先手抽 3 張、後手抽 4 張加幸運幣；先手第 1 回合水晶 1/1，再抽 1 張（手牌 4 張） |
| A2 | 同一組牌組、同一個種子、同一串行動 | 每一步的狀態完全相同 |
| A3 | 複製對局後在複本上行動 | 原本的對局不受影響 |
| A4 | 亂數改成「照記錄序列回傳」 | 依序回傳記錄的結果；要求的類型或範圍不符就回報不同步、不再繼續 |

## B. 回合與法力

| # | 情境 | 期望 |
|---|---|---|
| B1 | 回合開始 | 水晶上限 +1（最多 10），補滿可用水晶，抽 1 張 |
| B2 | 使用幸運幣 | 本回合可用法力 +1，可以超過 10（例如 10/10 → 11/10）；下回合照常補滿到上限 |
| B2a | 10/10 時使用幸運幣 | 11/10 |
| B3 | 打出超載 1 的卡（圖騰魔像） | 下個回合開始時鎖住 1 顆（可用＝上限 −1），再下個回合解除 |
| B4 | 手牌已有 10 張時抽牌 | 抽到的牌直接摧毀（爆牌），牌庫 −1 |
| B5 | 牌庫空了還要抽牌 | 疲勞傷害：第 1 次 1 點、第 2 次 2 點……，雙方各自累計 |
| B6 | 回合結束 | 換對方行動；對方手下的攻擊次數在他的回合開始時重置 |

## C. 出牌

| # | 情境 | 期望 |
|---|---|---|
| C1 | 出手下 | 費用不超過可用水晶才能出；扣水晶、放到指定位置（0 到目前隻數），右邊的手下往右移 |
| C2 | 戰場已有 7 隻 | 不能出手下 |
| C3 | 剛出場的手下 | 當回合不能攻擊；有衝鋒的可以立刻攻擊；有衝刺的當回合只能攻擊手下 |
| C4 | 出武器（例如奧達奇戰刃，3 費 2/2） | 扣 3 點法力；英雄裝上武器，攻擊力 2、耐久度 2 |
| C4a | 卡表的武器耐久度 | 奧達奇戰刃的耐久度是 2（`tw_all.json` 把武器耐久度放在 `health`，`durability` 是 0，產生器要處理） |

## D. 攻擊與關鍵字

| # | 情境 | 期望 |
|---|---|---|
| D1 | 手下互打 | 雙方同時造成等於攻擊力的傷害；生命歸零的在攻擊結束後死亡、移出戰場 |
| D2 | 對手有嘲諷手下 | 只能攻擊嘲諷手下，英雄和非嘲諷手下都不能選 |
| D3 | 潛行 | 對手不能把它選為攻擊目標；它攻擊後失去潛行；潛行中的嘲諷不強制對手先打它 |
| D4 | 聖盾術 | 吸收一次傷害並失去聖盾術，之後正常受傷 |
| D5 | 致命劇毒 | 對手下造成 1 點以上傷害就消滅它；被聖盾術擋下則無效；對英雄沒有特殊效果 |
| D6 | 風怒 | 每回合可以攻擊 2 次 |
| D7 | 生命竊取 | 造成傷害時，自己的英雄回復等量生命，最多到 30 |
| D8 | 攻擊力 0 | 不能攻擊 |
| D9 | 凍結 | 在對方回合被凍結的角色，下一個自己的回合不能攻擊，那個回合結束時解凍 |

## E. 英雄、武器、護甲、勝負

| # | 情境 | 期望 |
|---|---|---|
| E1 | 英雄用武器攻擊 | 攻擊力＝武器攻擊力；每攻擊一次耐久 −1，歸零時武器摧毀 |
| E2 | 英雄攻擊手下 | 英雄也會受到那隻手下的反擊傷害 |
| E3 | 已有武器時裝新武器 | 舊武器被摧毀 |
| E4 | 有護甲的英雄受傷 | 先扣護甲，不夠才扣生命 |
| E5 | 英雄生命歸零 | 遊戲結束，對方獲勝；雙方同時歸零為平手 |

## F. 合法行動

| # | 情境 | 期望 |
|---|---|---|
| F1 | 列出合法行動 | 可出的手牌（手下附上所有可放的位置）、所有可攻擊的組合、結束回合；格式和 difftest 相同 |
| F2 | 不合法的行動 | 回報錯誤，狀態不變 |

## G. 差分測試（第 1 階段驗收）

| # | 情境 | 期望 |
|---|---|---|
| G1 | 卡池 | RosettaStone 已實作、數值和關鍵字跟我們一致、敘述只有關鍵字（或沒有敘述）的手下，不分系列（目前 134 張）；由 difftest 產生清單並納入 git |
| G2 | `difftest run --engine emberstone --pool keywords --games N` | 先在 RosettaStone 記錄隨機對局，再讓 Emberstone 用同樣的行動和亂數重播，逐步比對；不使用英雄技能 |
| G3 | 驗收 | 1000 局沒有任何不一致；RosettaStone 本身的錯誤（逾時、當機）不算 |
| G4 | RosettaStone 的暫時法力上限 | 加 patch `0004`，讓 RosettaStone 的幸運幣照現行規則超過 10（B2a 在橋接程式上成立） |

## H. 速度量測

| # | 情境 | 期望 |
|---|---|---|
| H1 | `emberstone bench` | 用 G1 的卡池隨機組牌、隨機對局 N 局，輸出每局平均時間，以及第 10 回合複製一次對局的時間 |
| H2 | 門檻 | 這階段只輸出數字、不設門檻；門檻（一局 ≤ 0.5 ms、複製 ≤ 5 μs）到第 3 階段用批次 A 的牌組驗收 |

## 實作結果（2026-11-01）

- 規則測試 A–F：`crates/emberstone-core/tests/` 共 36 個，全部通過。
- 差分測試 G3：`difftest run --engine emberstone --pool keywords --games 1000 --seed 1` → 一致 1000/1000，RosettaStone 錯誤 0 局。
- 速度 H1（Windows、release、10000 局）：每局平均 0.117 ms、第 10 回合複製一次 0.60 μs。

### 對照時發現的 RosettaStone／橋接程式問題（已修正，不是 Emberstone 的規則改動）

| 問題 | 處理 |
|---|---|
| RosettaStone 的幸運幣 `GAME_005` 沒有定義效果，打出去什麼都不做 | patch `0004-coin-temp-mana.patch` 補上「+1 暫時法力」，同時拿掉 10 的上限（G4） |
| 橋接程式快照的 `fatigue` 讀玩家的 FATIGUE 標籤，永遠是 0 | 改讀英雄的疲勞累計 |
| 橋接程式把「剛出場的衝刺手下打英雄」列為合法行動（執行時什麼都不做） | 列合法行動時再用 `IsValidAttackTarget` 過濾 |

### 尚未對照、留到之後的差異

- RosettaStone 的英雄在對手回合被攻擊時會用武器反擊；現行規則是武器只在自己的回合有作用。Emberstone 照現行規則。第 1 階段卡池沒有武器，第 3 階段納入武器時再列給使用者裁定。
- 卡表的武器耐久度修正後，`data/batches.tsv` 的武器分類仍依英文卡表的原始欄位比較，武器多半被分到批次 B；第 3 階段處理。
